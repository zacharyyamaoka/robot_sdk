  • Callers: everything we build from now on. They depend on two message types, not on a robot.

Why a separate manager, not "the JCC is the mux": if the JCC were also the one writer, it would be a box with two jobs (running recipes and arbitrating the bus), and the JTC would always be downstream of it. With the manager as the mux, the JCC and JTC are symmetric peers. A cell with no recipes is just JTC → manager → bus, and the manager is ~1 small file with one rule set (claims, priority, stop wins). This reverses my earlier "you don't need a manager". You were half right: you don't need a big one, and the one on main is small.

The cost: a wire hop between JCC, JTC and manager. like_keras places a System in one process at one rate (dep.place(cell.arm, process="controller", hz=...)), so the boxes tick in order in one step, with no extra lag if those wires aren't lagged.
